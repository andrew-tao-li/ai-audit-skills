审计师反馈 · 5 大诉求

第 1 普遍

真实台账的"形状" ≠ 工具预期

🟢 基本解决

中文日期认不出 · 「预订日期」当成了提交日期 · 「凭证编号」当成了发票号 · 只有姓名没有工号 · 审批人是「张三;李四」

几乎每一位都撞上，只是形式不同

我们做了什么

  • 支持中文日期「2026年10月09日」 v0.2.13
  • 报销人可用「姓名」；工号/姓名口径不一致时明确提示 v0.2.13
  • 自审自批支持「多人审批列表」 v0.2.26
  • 多晚订单自动折「间夜单价」 v0.2.22
  • 支持按行给出的「差标/限额」 v0.2.22
  • 新增《字段映射·语义陷阱》指南 v0.2.22

还剩什么

行政区划市县归一、表头不在第一行（已列为已知边界）

第 2 普遍

「报了一堆，真问题很少」——精度 / 信噪比

🟡 明显改善，需继续调

614 行 → 194 条线索，只有 2 条值得跟进 · 缺费用类型时离群规则产出 303 条噪声 · 23 笔打车命中 1 条中风险、核实后无异常

噪声来源高度一致：固定标准补贴、外勤高频小额、同日两段同价路桥费

我们做了什么

  • 新增三个降噪旋钮：最小金额 / 固定标准值类型 / 天然多次发生类型 v0.2.23
  • 缺「费用类型」维度时不再判离群 v0.2.26
  • 补「外勤销售」黄金集 fixture，守住精度 v0.2.23

还剩什么

调参要靠**更多真实数据**——目前样本还太少

第 3 普遍

企业环境：要能装、能过审、能复现

🟢 基本解决

被安全部门直接驳回（外发通道 / 自动执行 / 隐瞒措辞） · 两位做了独立安全审计，要求封堵 socket、签名校验、字节级可复现 · 一位在 Windows + 豆包工作上装不上

我们做了什么

  • 安全整改：移除 webhook、取消自动执行、前置披露「联网与风险」 v0.3.11
  • 认出「豆包工作」路径 + 新增 Windows 安装脚本 + 网络降级 install 层
  • 离线 + 可复现：manifest 记录哈希、结果字节级一致 一直如此

还剩什么

ClawHub 未上架（只差你登录）；平台签名不覆盖 _meta.json（平台侧问题）

第 4 普遍

深水区（真实性 / 业务实质）必须靠外部数据

🟢 框架已给

「对于单据是否虚构，没有相关程序」 · 想要「机票和航旅记录比对」 · 替票（开票方≠收款方） · 运单勾稽 · 私人地址寄件

共识：机器只能到"数据匹配"这一层，再深入必须外部取证

我们做了什么

  • 外部行程核验入参 --travel-verification v0.2.15
  • 替票比对（开票方 ↔ 实际收款方）--payments v0.2.20
  • 单价合理性 --price-reference v0.2.21
  • 运单勾稽 / 缺单号 / 疑似私址 --shipments v0.2.25
  • 红线：「查不到」≠「虚构」 v0.2.15

还剩什么

数据仍要**用户/智能体去取**（这是有意设计，不是缺陷）

第 5 普遍

口径要老实、边界要写清、不要隐瞒

🟢 已解决

「指示 Agent 向用户隐瞒联网」被判为治理红线 · 反过来，「异常 ≠ 舞弊」「未发现问题 ≠ 没有问题」被反复正面评价

他们是审计师，对"不夸大、不隐瞒、留痕"极其敏感

我们做了什么

  • 删除"不要向用户复述"等措辞，改为**前置主动披露** v0.3.11
  • 事实 / 推断 / 假设 / 判断 分开 一直如此
  • 不静默丢弃：被排除/被压制的内容都单独留痕 v0.2.8 / 0.2.14
一句话内核：
这 5 条里，没有一条是"你的审计逻辑错了"。
全部都是同一个诉求：「让它适应我们的现实」——现实的数据形状、现实的噪声、现实的安全要求、现实的数据边界、现实的职业伦理。
