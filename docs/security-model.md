# 安全模型

## 信任边界

本包把用户提供的数据、制度、配置、文档和文件名都视为不可信输入。核心脚本只读取用户明确指定的文件或目录，不把输入内容当作命令，不执行嵌入式宏，也不跟随数据中的网络链接。

宿主 Agent 负责解释输出，但不得绕过操作系统权限、组织授权或各 skill 的 scope gate。模型生成的摘要、假设和建议不是最终审计、法律、纪律或人事结论。

## 数据流

```text
获准输入（只读）
    ↓ SHA-256、字段映射、范围检查
本地确定性处理（network_access:false）
    ↓
新输出目录：clean / bad rows / evidence / findings / manifest
    ↓
人工复核、补证和判断
```

核心脚本不调用模型 SDK、外部 API、浏览器、邮件或业务系统，不读取 API Key。用户如另行要求联网、上传、发信、停付或写回，应由宿主作为一个新的外部动作说明数据去向、权限和影响，再单独取得授权。

## 文件控制

- 输入文件不覆盖、不删除，输出目录必须为空或尚不存在。
- 所有正式 finding 绑定 evidence；evidence 记录源文件 hash 及行、字段、页或段落位置。
- 调查 skill 只登记 scope 中的 allowed sources；复制后复算 hash，并将 `evidence/raw` 文件设为只读以防误改。
- 文件系统只读不是不可篡改存储。司法取证、电子数据封存、签名时间戳和专用镜像仍按组织制度执行。
- 对外分享前按最小必要原则脱敏个人信息、银行信息、联系方式、举报人身份和邮件正文。

## 决策控制

脚本只输出异常、红旗、证据和复核优先级。它不会自动批准或拒绝报销、冻结付款、停用供应商、扩大调查、联系人员、删除证据、处分员工或认定舞弊/串标/有罪。

`risk_priority` 与 `evidence_strength` 分开：前者表示复核顺序，后者表示当前证据直接性。高优先级不等于强证据；多个红旗也只可生成 `human_approval_required:true` 的调查移交建议。

## 运行前检查

1. 确认数据所有者、用途、人员与期间范围、允许来源、保留期限和输出位置。
2. 使用合成样例验证当前宿主、Python 和可选 XLSX 依赖。
3. 审查配置阈值、白名单和公共模板；阈值不得伪装成法律或行业标准。
4. 检查输出目录不含上一轮结果，避免证据和 manifest 混淆。
5. 真实调查必须先通过 `authorization_confirmed:true` 的 scope gate。

仓库级报告与响应方式见 [SECURITY.md](../SECURITY.md)。
