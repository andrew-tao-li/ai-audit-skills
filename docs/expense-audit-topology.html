一、主干流程

② 洗涤与映射

  • 33 个标准字段 自动别名匹配
  • 中文日期「2026年10月09日」等
  • 坏行隔离 → bad_rows.csv
  • 按审批状态过滤（可选）
  • 多列金额求和（可选）
→

③ 规则引擎（10 个域）

  • A 重复与复用 · B 制度与阈值

  • E 统计离群 · F 凭证/票据真实性
  • G 外部核验 · H 差旅交叉
  • I 时空 · J 数据治理
→

④ 输出

  • 给人看：dashboard.html / summary.md / findings.csv / findings.jsonl

  • 数据面：clean_expenses.csv / bad_rows.csv / data_quality.md

三、可选输入 → 会"唤醒"哪些能力

参数你提供什么会新增的规则不提供时
--policy制度 JSON（限额/审批阈值/节假日…）超制度上限 · 拆单 · 大额低层级审批 …相关规则自动跳过并说明
--field-map确认后的字段映射（修正映射，减少误报）自动猜别名
--travel-requests出差申请单差旅无出差申请不参与
--attendance打卡/考勤称外地但当天公司打卡 · 打卡城市不符不参与
--travel-verification外部航班核验结果行程核验不符 / 未找到不参与（查不到≠虚构）
--payments支付/收款记录开票方≠实际收款方（替票）不参与
--price-reference市场价格参考单价高于参考市场价不参与
--shipments运单台账运单勾稽 / 缺单号 / 疑似私址不参与
--allowlist白名单（已知无风险）（压制，写 suppressed_findings.csv）不参与
帕累托保证：上面每一项都是可选。不给 → 完全等同于旧版；给了 → 才多出对应能力。

五、边界与红线（必须与上面一起看）

它不能做

  • 不判断业务实质（费用是否真实发生）
  • 不做舞弊/拒付认定——异常 ≠ 舞弊
  • 不联网、不连银行流水；不做发票验真（需外部数据，见 G）
  • 制度阈值只能来自你给的制度

人工必查（脚本不覆盖）

  • 发票真伪 · 关联交易与利益冲突
  • 票据原始凭证 · 报销业务实质
  • 关联方资金往来 · 审批权限匹配 …
两句话记住它：① 机器负责全量找线索，人负责定性； ② 未发现问题 ≠ 没有问题。
