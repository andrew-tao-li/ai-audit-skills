# 审计方法与解释边界

## 数据先于模型

先盘点行数、字段、空值、类型、重复和主键；再定义数据合同；只标准化分析需要的字段；任何丢弃或转换都写入日志。合并多表时要核对合并前后行数和匹配覆盖率。

## 确定性分析先行

重复号码、日期顺序、共享银行账号、阈值超限、拆单和数学相似度由规则或统计脚本完成。Agent 不应重新“猜”这些结果。统计异常优先用中位数、MAD、IQR 等稳健方法；有随机性的模型必须固定随机种子并记录参数。

## 弱信号与合理解释

周末、共享注册地址、统一模板、独家供应商等都可能有合理解释。弱信号不能单独升为高风险；白名单、公共模板和业务例外要作为正式配置保留。

## 证据与语言

使用 `finding`、`anomaly`、`red flag`、`risk indicator`、`lead`。避免“已证实舞弊”“串标成立”“有罪”等结论性表述。每个发现都应写清来源、规则、已知事实、推断、开放问题、补证动作和人工复核边界。
