# 第一版关键设计取舍

## 为什么不是“大 Prompt”

报销重复、日期先后、共享账号、金额阈值、稳健离群和文本余弦相似度都可重复计算。第一版把这些工作放在离线脚本中，让宿主 Agent 只承担制度理解、模式归纳、替代解释、补证问题和沟通。这样同一输入能在不同 Agent 上得到一致的基础事实。

## 为什么费用离群先用 MAD

项目既有案例验证了 Isolation Forest 对全量费用筛查的价值，但第一版优先采用中位数与 MAD：参数少、结果易解释、无需额外模型依赖，也便于在表格或 SQL 环境复现。小样本或 MAD 为零时明确跳过，不把“算法无法判断”写成“没有异常”。后续可把固定随机种子的 Isolation Forest 作为可选模块，并要求与规则结果分别呈现。

## 为什么投标文本使用字符 n-gram TF-IDF

字符 n-gram 对中文分词依赖小，可离线运行，也能发现措辞、错别字和句式的局部复用。分析只在同一标段内比较，并支持移除公共模板短语。高相似度只是回到原文复核的线索；当前阈值是运行配置，不是法律或行业标准。

## 为什么先做精确共享属性，不自动模糊合并实体

规范化后的银行账号、电话和邮箱属于较强、可解释的连接；地址更容易因园区、集团或注册代理产生误报，因此必须支持白名单。第一版不自动把名称相似的两个主体合并，也不做不可解释的“同一实体概率”。这牺牲了一部分召回率，换取更可靠的证据链和更低的误指控风险。

## 为什么风险优先级与证据强度分开

高金额、关键流程或多模块聚合可能需要优先复核，但现有证据仍可能很弱。`risk_priority` 表示先看什么，`evidence_strength` 表示现有证据有多直接。两个维度分开可避免把高优先级误读为“已证实”。

## 为什么调查必须先通过 scope gate

调查材料通常比审计台账更敏感。脚本在读取内容前要求明确目的、授权、期间、人员、允许来源和禁止联网；越界结构化记录单独列出。原件登记、哈希与只读副本先于摘要和假设，且证据矩阵必须同时保留支持材料、反证、替代解释和缺口。

## 为什么只维护 canonical skill

三个 skill 的核心 `SKILL.md` 使用开放字段和相对路径，脚本不调用任何模型 API。Codex、Pi 和 OpenClaw 可直接发现 canonical 目录；WorkBuddy 等平台的展示字段或导入差异放在 `adapters/` 说明，不复制另一套方法正文，避免不同平台版本长期漂移。
