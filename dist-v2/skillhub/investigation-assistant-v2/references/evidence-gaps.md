# 证据缺口与"不利推定"的边界

> **本文件是给人工复核用的清单，脚本不参与判定、不算分、不产生结论。**
> 目的：把「查不到」与「已证实」严格分开，避免把"没拿到"读成"有问题"。

---

## 一、先把缺口分成三类（不要混着写）

| 类型 | 定义 | 记录方式 | 对置信度的影响 |
|---|---|---|---|
| **调查方缺口** | 因为**我们**的权限、技术、人力或时间没拿到 | 记为「调查方缺口」+ 说明受限于什么 + 替代获取路径 | **应当下调**相关事项的置信度（这是我们自己的不足，不能算在对方头上） |
| **被调查方缺口** | 因为**对方**未提供 / 拒绝提供 / 拖延 | 记录：**请求了什么、何时请求、对方的提供义务、期限、对方回应、客观障碍** | **默认只作为"配合风险"信号**——**不自动证明相关指控，也不自动提高置信度** |
| **环境缺口** | 客观条件导致不可获取（如系统已下线、数据已过保存期） | 记为「环境缺口」+ 替代获取路径 | 不下调、不提高；在报告中如实说明"该事实无法核实" |

> **一句话**：**缺口首先表示"不知道"**，不代表"有问题"，也不代表"没问题"。
> 与费用技能的「**查不到 ≠ 虚构**」是同一条红线。

---

## 二、把缺口写进产物时注意

- `evidence_matrix.csv` 的 `missing_evidence` 栏：写**缺什么**，不要写成"对方隐瞒了什么"。
- `hypothesis_register.csv` 的 `missing_evidence` 栏：与上同。
- findings 的 `open_questions`：写**待补证据**，不要写成"待对方交代"。
- 导出/取数失败的行：进 `out_of_scope_rows.csv` / `unparseable_rows.csv`（**不静默丢弃**），并在 `data_quality.md` 计数。

---

## 三、「不利推定」的人工判定清单（**必须全部满足**才可讨论）

> ⚠️ **只有在下列条件全部满足、且经授权人员复核后**，才可以"有限地"讨论对某方不利的推论。
> **脚本永远不做这个判断；本清单只供人工勾选。**

- [ ] 1. 该方对该材料**存在明确的保存义务或提供义务**（制度 / 合同 / 法规 / 授权文件）
- [ ] 2. 我们的请求**内容具体、范围合理**、且在授权范围之内
- [ ] 3. 给了**充分期限**并留有书面凭证（时间、渠道、内容）
- [ ] 4. **客观障碍已排除**（不是系统故障、不是范围过大、不是误发给无权人员）
- [ ] 5. 已确认**不存在其他合法获取途径**（或已穷尽）
- [ ] 6. 由**有权人员**（合规 / 法务 / 调查负责人）复核并明确同意
- [ ] 7. 即便满足以上全部，**推定强度仍须显著低于直接证据**，并在报告中写明**推定的前提与限度**

**任何一项未勾选 → 不得用于不利推定**，只能作为"配合风险"记录，并继续保持事项 open。

---

## 四、与本技能产物对应的落点

| 内容 | 写到哪 |
|---|---|
| 缺口分类与归因 | `evidence_matrix.csv` / `hypothesis_register.csv` 的 `missing_evidence`；`data_quality.md` |
| 缺口对置信度的影响 | 人工在 findings 的 `open_questions` 里写明；**脚本不改结论** |
| 越界/坏行 | `out_of_scope_rows.csv` / `unparseable_rows.csv`（留痕，不静默丢弃） |
| 推定结论 | **不进脚本产物**；由调查报告撰写人依第三节清单决定 |
