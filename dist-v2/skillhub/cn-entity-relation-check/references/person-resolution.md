# 自然人身份消歧（person-resolution）

## 核心原则

自然人姓名不是唯一标识。`person.name == "张三"` 不能作为一个确定的自然人实体。

自然人至少需要一种锚点：

- 数据商返回的稳定 `person_id`；
- 「姓名 + 已确认任职企业」；
- 「姓名 + 已确认历史任职企业」；
- 其它由结构化工商数据源建立的唯一人员 ID。

## 三种情况

1. **用户已提供锚点**（如「上海甲公司的张三」）：直接用「公司 + 姓名」锚定。
2. **公司 + 人名**：先查该公司的法人/股东/董监高/实控/UBO 是否直接出现该人名；只有一个明确对象且 Provider 有稳定 person_id 才继续。
3. **人 + 人**：不建议直接做姓名碰撞。先用人员工商查询工具获取候选任职公司，尽量形成稳定 person_id；多候选时向用户展示，由用户补充任职/曾任企业后继续。

## 重名硬规则

若 `same_name_candidates > 1` 且无法通过 Provider 稳定 ID 消歧 → `NEEDS_VERIFICATION`。

不得依靠年龄猜测、地区猜测、搜索排名、新闻知名度、模型常识进行合并。

## 隐私

第一版不主动索取身份证号、银行卡号、私人手机号、家庭住址等高敏感信息。本 skill 做的是「企业身份消歧」，不是「私人画像」。
