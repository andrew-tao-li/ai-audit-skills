# 行程/票据外部核验指南（`--travel-verification`）

> **先读这一句**：**本技能不做任何联网查询。** 这张核验表**由你（或你的智能体）用你自己的方式取得后提供**。
> 技能只做一件确定、可复现的事：**把你的核验结果与报销单据逐字段比对**。

---

## 为什么这样设计（而不是让技能自己联网）

1. **安全与合规**：很多使用方的安全要求是「审计工具不得外联」。技能本体**零网络**，才能通过安全审查。
2. **这类数据本身是商业授权数据**：航班 / PNR / 发票真伪**不是**"找个免费 API"就能拿到的（见下表）。
3. **确定性**：把外部事实"快照"成输入文件后，运行结果**可复现、可追溯**（文件哈希进 `run_manifest.json`）。

---

## 怎么取得核验数据（由你 / 你的智能体完成）

| 数据 | 常见来源 | 说明 |
|---|---|---|
| 航班是否执飞 / 日期 / 航段 | 航司官网、航旅纵横（消费端）、FlightAware / Flightradar24、GDS（Amadeus / Sabre / Travelport，商业） | **航旅纵横没有官方开放 API**；抓取可能违反其条款，责任在使用方 |
| 增值税发票真伪 | 国家税务总局全国增值税发票查验平台 | 官方，但**有验证码、限制自动化**；建议人工核对 |
| 境外票据 | 出票平台 / 航司 / 酒店的订单页、银行流水、登机牌 | 以能拿到原始记录为准 |

> ⚠️ **合规提醒**：请以各来源的**官方条款**为准。抓取"需授权 / 禁止自动化"的来源，**风险由使用方承担**——
> 这也正是我们**不把联网写进技能**的原因之一。

---

## 输入格式

CSV / XLSX，**一行 = 一张报销单的核验结果**：

| 列 | 含义 |
|---|---|
| `expense_id` | **必填**：对应报销台账里的单据号 |
| `flight_no` / `travel_date` / `depart_city` / `arrive_city` / `passenger` | 外部**实际**查到的值；**查不到就留空** |
| `source` | 来源（会写进 finding，供复核）；建议必填 |
| `source_reliability` | 可选：`official` / `commercial` / `consumer` / `unknown` |

示例：

```csv
expense_id,flight_no,travel_date,depart_city,arrive_city,passenger,source
F1,CA1234,2026-10-09,北京,上海,EMP1,航司官网
F2,,,,,,航旅纵横
```

---

## 会产生什么

| 情况 | 结果 |
|---|---|
| 查到且一致 | **不产生** finding |
| 查到但不一致（航班号 / 日期 / 方向 / 乘机人） | `travel-verification-mismatch`（**强**） |
| **在给定来源中查不到**（外部字段全空） | `travel-verification-not-found`（**弱**） |
| 报销单没有对应核验行 | 不核验，只在 `data_quality.md` 里报一个计数 |

---

## 红线：**「查不到」不等于「虚构」**

- 外部来源可能**覆盖不全、字段不全、查询范围有限**——所以"没匹配到"**只是弱信号**，用途是提示"换更权威的来源重查"；
- 结论里会**明确写出**这一点，避免被当成认定；
- 这与 `cn-entity-relation-check` 的「**没查到 ≠ 不关联**」是同一条原则。

---

## 谁负责联网

**你（或你的智能体）。** 宿主智能体一般自带联网/搜索/MCP 能力——**由它在你的许可下取数，再喂给本技能**。
这样：**取数的责任和使用者的合规评估在你这边**，而**被审计的那个技能包始终是干净的**。
