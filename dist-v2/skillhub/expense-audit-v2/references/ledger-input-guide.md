# 会计账 / 明细账接入指南（输入不是报销台账时看这份）

> **什么时候看这份**：你要分析的不是"报销登记台账"，而是**会计资料**——
> 费用分类明细账、序时账、明细表、余额表、试算平衡表，往往是**多个 .XLS/.XLSX 文件**，
> 没有员工号、没有审批人、没有发票号列。
>
> **结论先说**：**能跑**。但需要你先做一步"统一映射"，把会计资料变成技能能吃的**一套字段**。
> 下面这套办法来自一位真实审计师的实测（石化/能源集团 2021–2022 费用账，4 个 .XLS → 136 条有效记录）。

---

## 一、五步法

### 第 1 步：分清「交易级」和「非交易级」

| 文件 | 是不是交易级 | 处理 |
|---|---|---|
| 费用分类明细账 / 序时账 / 费用明细表 | ✅ 是 | **要喂** |
| 余额表 / 试算平衡表 | ❌ 不是（期间余额，不是一笔笔业务） | **不要喂**——喂进去只会制造噪声 |
| 总账（仅科目汇总） | ❌ 不是 | 不要喂 |

> 判据：**一行是不是一笔真实业务**？是 → 喂；只是余额/汇总 → 不喂。

### 第 2 步：检查文件之间有没有**包含关系**（最容易重复计入）

真实案例：那份「费用明细表」其实**是序时账的费用子集**——两张都喂进去，同一笔业务会被算两次。

**做法**：先各看几行、对一下同期同额是否重复。**有包含关系就只留最全的那一张**，
并在交付时写明"某某表因与序时账重复，未并入"（**留痕，不静默丢弃**）。

### 第 3 步：统一字段映射

把各表的列**映射成同一套字段**，再拼成一张表喂给技能。核心字段：

| 技能字段 | 会计账里通常对应 | 备注 |
|---|---|---|
| `expense_id` | **凭证号 + 行号**（自己拼一个唯一值） | 必须**每行唯一** |
| `expense_date` | 业务/记账日期 | 日期格式见 `field-mapping-guide.md` |
| `amount` | 借方发生额（费用类） | 注意别把贷方冲销也算进去 |
| `employee_id` | **没有这一列 → 从摘要抽**（见第 4 步） | 抽不到就**每行唯一占位** |
| `expense_type` | 会计科目名称 / 摘要里的费用类别 | 有它才有"同类异常高额"这个维度 |
| `vendor_name` | 摘要里的对方名称（常缺） | **空着没关系**——空值率高是正常的 |
| `business_purpose` | 摘要 | 直接放摘要原文即可 |

> **不要**把「余额」「累计」这类列当 `amount`；也**不要**用凭证号当 `employee_id`。

### 第 4 步：从摘要里抽人名（并保证占位唯一）

会计账的摘要常写成 `*[员工甲]报销_销售部`、`张三 差旅费` 这类形式。可以用正则抽：

```
*姓名报销  →  employee_id = 姓名
抽不到     →  匿名R1 / 匿名R2 / …（**每行唯一**）
```

⚠️ **两条铁律**（**这是真实踩过的坑**）：

1. **抽不到的行，绝不能共用同一个占位值**——否则技能会认定"这是同一个人"，凭空造出假的重复。
2. **每行唯一占位**的行仍然会参与**金额类**和**离群类**分析，只是**不参与同人分组**——这正是你想要的。

> 真实教训：把**含凭证号**的匿名 ID 用在一笔「计提工资」凭证的 15 个部门明细上 →
> 15 行共享同一 ID → 判出 1 条假「同员工同日同金额重复」。改成每行唯一后消失。

### 第 5 步：跑之前先体检，跑完先看 `data_quality.md`

```bash
python3 scripts/run_expense_audit.py --check-env                 # 先看环境（含 .xls/.xlsx 支持）
python3 scripts/run_expense_audit.py \
  --input consolidated_expenses.csv --policy policy.json --output ./out
```

**先看 `data_quality.md`**：字段映射、空值率、坏行、以及**哪些规则被跳过**，都在这里。

## 二、老格式 `.XLS`（Excel 97-2003）怎么办

会计档案里 `.XLS` 极常见。两种办法：

| 办法 | 做法 |
|---|---|
| **A. 让技能直接读（推荐）** | 离线安装可选依赖：`pip install xlrd` → 直接 `--input xxx.xls`。用 `--check-env` 看 `xls_support` 是否为 `available` |
| **B. 先转格式** | 用 Excel / WPS 另存为 `.xlsx` 或 **UTF-8 CSV**，再喂给技能 |

> `xlrd` 只用于**读文件**，**不会联网**。不安装也不影响 CSV/XLSX。

## 三、会自动跳过什么（**这是设计，不是失败**）

会计账通常**没有制度、没有发票号、没有审批人**，所以下列规则**会自动跳过**，并在 `data_quality.md` 写清原因：

| 缺失的东西 | 自动跳过的规则 |
|---|---|
| 费用制度（`policy.json` 的 `limits` / `approval_thresholds`） | 超制度上限、拆单报销 |
| 发票号列 | 发票号重复、发票跨人复用、发票连号 |
| 审批人列 | 自审自批、大额低层级审批 |
| 提交日期列 | 提交早于消费 |

**仍然会跑的**：同员工同日同金额、金额近似、**同类异常高额**（统计离群）、周末/节假日信号。

> 想让更多规则生效，见第四节。

## 四、让更多规则生效（按投入产出排序）

| 补什么 | 点亮什么 |
|---|---|
| **费用制度**（限额、审批阈值） | 超制度上限、拆单报销 —— **投入最小、价值最大** |
| **发票号列**（从凭证里补） | 发票号重复、发票跨人复用 |
| **审批人列** | 自审自批、大额低层级审批 |
| **出差申请 / 打卡记录** | 差旅交叉核验（`--travel-requests` / `--attendance`） |
| **支付/收款记录** | 替票比对（`--payments`） |

---

## 五、别做的事

- ❌ 不要把**余额表 / 试算平衡表**当明细喂进去；
- ❌ 不要**用凭证号 / 单据号当人员标识**；
- ❌ 不要把有**包含关系**的多张表一起喂（会重复计入）；
- ❌ 不要因为"会计账口径"就把它当成"报销台账"——**两者口径不同**，结论要说明输入来源。

---

## 六、边界（务必向用户转达）

- 输入是会计账而非报销单时，**人员、商户多是从摘要推断的**，可靠性低于结构化台账；
- 没有制度与发票/审批数据时，**制度类与发票类结论缺席**——这**不代表没有问题**，只代表**没查**；
- 本技能只验证**数据之间对得上**，**不验证业务是否真实发生**；**异常 ≠ 舞弊**。
