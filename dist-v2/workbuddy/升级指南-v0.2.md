> "请帮我用 expense-audit-v2 / procurement-fraud-v2 / investigation-assistant-v2 skill 包内自带的合成样例跑一次，验证它跑得通。"

investigation-assistant-v2）跑一次测试。它们包内有自带的合成样例，

3. **AI 会自动**：
   - 找到三个 v0.2.0 skill
   - 用包内合成数据跑测试

   - 给出是否推荐的判断

4. **你只需要做的事**：
   - 听 AI 的报告
   - 觉得 OK 后，把旧版 skill 卸载即可（让 AI 帮你卸载）

## 三、详细升级路径

### 路径 A：纯用户（不懂命令行）

```
对 AI 说："请帮我升级到 expense-audit v2.0.0，
文件在 dist-v2/zips/expense-audit-v2.zip。
先测试新版本，确认能用，再告诉我怎么卸载旧版。"
```

AI 会：
1. 上传 v0.2.0 ZIP 到宿主
2. 用包内合成样例跑测试
3. 报告测试结果（finding 数 + network_access:false + 完整产物）
4. 提示你卸载旧版的步骤

### 路径 B：半技术用户（懂 Python 但不想管细节）

```
对 AI 说："请帮我升级 audit skill 包：
1. 校验 dist-v2/zips/ 下的 3 个 ZIP 哈希
2. 解包到宿主 skill 目录
3. 跑每个 skill 的 --check-env
4. 跑每个 skill 的合成样例
5. 用 evals/validate_pack.py --run-tests 跑测试
6. 报告对比新旧版本的 finding 数差异
7. 如果通过，提示我可以卸载旧版"
```

### 路径 C：完整迁移（系统管理员）

```bash
# 1. 校验哈希
cd dist-v2/zips && shasum -a 256 *.zip && cat ../SHA256SUMS

# 2. 解包到宿主 skill 目录
unzip expense-audit-v2.zip -d ~/.your-host/skills/expense-audit-v2/
unzip procurement-fraud-v2.zip -d ~/.your-host/skills/procurement-fraud-v2/
unzip investigation-assistant-v2.zip -d ~/.your-host/skills/investigation-assistant-v2/

# 3. 重启宿主（让 skill 被发现）

# 4. 跑全套测试
cd ai-audit-skills
python3 evals/validate_pack.py --run-tests

# 5. 端到端验证
python3 skills-v2/expense-audit-v2/scripts/run_expense_audit.py \
  --input skills-v2/expense-audit-v2/examples/input/expenses.csv \
  --policy skills-v2/expense-audit-v2/examples/input/policy.json \
  --output /tmp/v2-verify-exp

# 6. 卸载旧版
# 用户界面：技能列表 → 选旧版 → 删除
# 或命令：rm -rf ~/.your-host/skills/expense-audit/
```

## 四、v0.2.0 的"必看"配置变更

如果你之前在 v0.1.x 写过 config.json 或 scope.json，升级后 v0.2.0 会**拒绝未知键**。

### expense policy.json 新增合法键

```json
{
  "policy_version": "...",
  "default_currency": "CNY",
  "limits": [...],
  "approval_thresholds": [...],
  "near_duplicate_window_days": 7,
  "near_duplicate_amount_tolerance": 0.02,
  "split_window_days": 3,
  "weekend_check": true,
  "outlier_min_group_size": 5,
  "outlier_robust_z": 3.5,
  // ↓ v0.2.0 新增
  "holidays": ["2026-10-01", "2026-10-02"],  // 法定节假日列表
  "large_amount_threshold": 5000,             // 严重度分级的"大额"阈值
  "low_level_approver_keywords": []          // 低层级审批人关键词（可选）
}
```

### procurement config.json 新增合法键

```json
{
  "config_version": "...",
  // ↓ v0.2.0 新增
  "order_approval_direction": "forward",     // forward | either | strict
  "same_day_approval_grace": true,            // 同日审批豁免
  "new_vendor_days_threshold": 90,            // 新成立供应商天数阈值
  "new_vendor_amount_threshold": 50000,       // 新供应商首单金额阈值
  "order_amount_tolerance": 0.01              // 付款额 vs 订单额容差
}
```

### investigation scope.json 新增合法键

```json
{
  "case_id": "...",
  // ↓ v0.2.0 新增
  "holidays": ["2026-10-01"],                 // 范围控制节假日
  "context_from_other_skill": {...}            // 上游 skill 的移交上下文（保留用）
}
```

**如果你的旧配置里写了错误的键名（例如把 `approval_thresholds` 写成 `approval_threshold`），v0.2.0 会立即报错并提示所有合法键**。这是 v0.1.x 的静默忽略问题的彻底修复。

## 六、卸载 v0.1.x 的判断标准

**只有满足以下条件时才卸载 v0.1.x**：

- [ ] v0.2.0 三个 skill 的合成样例测试都通过
- [ ] v0.2.0 三个 skill 在原版 examples/input 上的 finding 数 ≥ v0.1.x（已验证：expense 15/15, procurement 11/10, investigation 一致）
- [ ] 你已确认 v0.2.0 的新规则（自审自批、发票跨人、新供应商等）对你业务的适用性
- [ ] 你已验证 v0.2.0 不会破坏你已有的 config.json 或 scope.json
- [ ] 你已经为新的 config 字段（holidays / large_amount_threshold / new_vendor_days_threshold 等）准备好对应配置

**如果不满足任何一项**，保留 v0.1.x 与 v0.2.0 并存，按"哪个适合用哪个"的方式调用。

## 七、常见问题

### Q1: 如果我在 v0.1.x 上传过旧 ZIP，现在还能用吗？

**能**。v0.1.x 和 v0.2.0 互不依赖。并存即可。

### Q2: v0.2.0 会破坏我现有的 data 文件吗？

**不会**。所有脚本都是只读输入、输出写入新目录，原文件不被修改。

### Q3: 如果升级后发现 v0.2.0 不适合，能回滚吗？

**能**。只要保留 v0.1.x 不卸载，回到 v0.1.x 只需在对话中点名 `$expense-audit`（不带 -v2）。

### Q4: v0.2.0 的新规则会让 finding 数量爆炸吗？

**不会**。v0.2.0 的新规则都是高信号（自审自批 / 跨人复用 / 新供应商 / 超额付款），触发条件严格。普通正常数据不会被误报。

### Q5: 我应该什么时候升级？

- **立即升级**：如果你目前的 v0.1.x 用得顺，且希望获得新规则
- **暂缓升级**：如果你对 v0.1.x 的产出完全满意，且新增规则不在你的审计范围
- **并行使用**：推荐——新规则用 v0.2.0，稳态规则用 v0.1.x

### Q6: v0.2.0 之后还会有 v0.3 吗？

会。当前规划：
- v0.2.0（已完成）：帕累托改进 + 配置契约 + 盲点补齐
- v0.3.0（计划）：制度回显确认闸门 + Windows 测试支架修复 + 黑盒测试基座
