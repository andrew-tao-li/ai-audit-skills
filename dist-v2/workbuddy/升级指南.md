**finding 数变多 = 发现更多潜在风险 = 帕累托改进的本意**。

## v0.2.0 新增配置字段（必须看的部分）

### expense policy.json 新增字段

```json
{
  "policy_version": "...",
  "limits": [...],
  "approval_thresholds": [...],
  // ↓ 以下为 v0.2.0 新增可选字段
  "holidays": ["2026-10-01", "2026-10-02", "2026-10-03"],
  "large_amount_threshold": 5000,
  "low_level_approver_keywords": ["助理", "实习生", "A901"],
  "as_of_date": "2026-12-31"
}
```

| 字段 | 用途 | 默认值 |
|---|---|---|
| `holidays` | 法定节假日列表（命中后触发 `holiday-signal`） | `[]` |
| `large_amount_threshold` | 大额阈值，超过则提升 risk_score | `5000` |
| `low_level_approver_keywords` | 审批人字段包含关键词 + 大额 → 触发 `large-amount-low-level-approval` | `[]` |
| `as_of_date` | `future-date` 规则的基准日 | 系统当前日期 |

### procurement config.json 新增字段

```json
{
  "config_version": "...",
  // ↓ 以下为 v0.2.0 新增可选字段
  "order_approval_direction": "forward",
  "same_day_approval_grace": true,
  "new_vendor_days_threshold": 90,
  "new_vendor_amount_threshold": 20000,
  "order_amount_tolerance": 0.01
}
```

| 字段 | 用途 | 默认值 |
|---|---|---|
| `order_approval_direction` | forward / either / strict | `"forward"` |
| `same_day_approval_grace` | 同日审批豁免 | `true` |
| `new_vendor_days_threshold` | 新供应商天数阈值 | `90` |
| `new_vendor_amount_threshold` | 新供应商首单金额阈值 | `20000` |
| `order_amount_tolerance` | 付款额 vs 订单额容差 | `0.01` |

### investigation scope.json 新增字段

```json
{
  "case_id": "...",
  // ↓ v0.2.0 新增可选
  "holidays": ["2026-10-01"],
  "context_from_other_skill": {...}
}
```

**如果你的旧配置里写了错误的键名，v0.2.0 会立即报错并提示所有合法键**。这是 v0.1.x 静默忽略问题的彻底修复。

## 常见问题

### Q1：升级后我的旧 config.json 还能用吗？

**能**。所有 v0.1.x 的字段在 v0.2.0 都是合法键。新字段都是可选的。但**如果旧配置有错别字**，v0.2.0 会立即报错——v0.1.x 是静默忽略。

### Q2：v0.2.0 会破坏我现有的数据文件吗？

**不会**。所有脚本都是只读输入、输出写入新目录，原文件不被修改。

### Q3：finding 数变多怎么办？

**这是好事**。v0.2.0 比 v0.1.x 多发现的 finding 都是潜在风险信号（比如连号发票、新供应商接大单等），不是误报。如果某个新规则对你的业务不适用，把它对应的配置项关掉即可（如 `holidays: []`）。

### Q4：能回滚吗？

**能**。保留 v0.1.x 不卸载，回到 v0.1.x 只需在对话中点名 `$expense-audit`（不带 -v2）。

### Q5：什么时候升级？

- **立即升级**：希望获得 v0.2.0 的全部新规则和修复
- **暂缓**：对 v0.1.x 完全满意，且新增规则不在你的审计范围
- **推荐并行**：稳态用 v0.1.x，新规则用 v0.2.0
