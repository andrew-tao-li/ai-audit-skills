# 业务实质性声明（business-substance）

## 为什么需要这段声明

报销审计的现实已经变了：

- **发票真实性不再是主要矛盾**。发票管理日益严格，企业普遍使用阿里商旅、汇联易等工具，发票本身的真伪、连号、重复等问题已大幅减少。
- **业务实质性才是主要风险**。真正的疑点在于「各项指标都对，但不符业务实质」——发票是真的、金额没超限、日期合规、就餐时间也正常，但当事人当时是否真的在宴请客户、是否真的出差，数据本身无法回答。

所以本 skill 必须在语言层面**明确、结构化地**划清这条边界，否则审计人员可能误以为「没发现问题 = 没问题」。

## 核心概念：合理保证 vs 绝对保证

- **本 skill 提供的是「数据匹配层面的合理保证」**：验证发票号、金额、日期、限额、审批流等数据之间的**一致性**。
- **本 skill 无法提供「业务实质层面的绝对保证」**：验证费用背后**业务是否真实发生**。

一句话：**我们验证的是「数据之间对得上」，不是「业务真的发生了」。**

## 结构化表达（已写入 summary.md）

```
## 业务实质性声明（请务必阅读）

本报告提供的是数据匹配层面的合理保证（reasonable assurance），不是业务实质的绝对保证。

- 已验证：发票号、金额、日期、限额、审批流等数据之间的一致性。
- 无法验证：费用背后业务是否真实发生。例：一笔合规的客情费——发票真实、
  未超限、日期合规、就餐时间正常——但当事人当时是否真的在宴请客户，无从判断。

因此请注意两点：
1. 未发现问题 ≠ 没有问题：本报告只覆盖「可被数据匹配到的异常」，
   未被标记的部分，其业务实质尚未核实。
2. 如需深入核查业务实质，请补充佐证：客户名单、会议/拜访记录、行程单、
   签到表、定位记录、业务往来凭证等。

审计工作在此只完成了一部分：数据匹配已完成，业务实质仍需更多数据佐证。
```

## 两个选择（给审计人员的出口）

1. **想深入**：提供更多数据，做更多匹配。以下证据可「证实或证伪」一笔费用的业务实质：
   - 客情费 → 客户名单、拜访/会议记录、签收单、合影、往来邮件。
   - 差旅费 → 行程单、机票/车票、住宿水单、打卡/定位记录、出差审批与事由。
   - 办公/采购 → 收货单、入库单、验收记录、领用登记。
   - 通用 → 业务合同、项目立项、付款流水、内部沟通记录。
2. **暂不深入**：至少记住「这份答案是有边界的」，未覆盖的部分不代表 OK。审计工作只做了一部分。

## 关键措辞原则

- **不软弱、不冤枉**：既不说「一切可疑」，也不说「已经查完」。明确「已验证什么、没验证什么」。
- **结构化、一眼看懂**：用「已验证 / 无法验证」「未发现问题 ≠ 没有问题」这样的对仗结构，让别人立刻抓住要点。
- **留出口**：始终给出「提供更多数据」这条可操作的下一步，而不是只抛一句免责声明。

## 适用范围

本声明当前固化在 `expense-audit-v2` 的 `summary.md`。同样的原则适用于采购（供应商交易的真实性）、
关联排查（公开工商关系 ≠ 真实利益输送）等领域，后续可按需扩展到其它 skill。
