# 行程/票据外部核验指南（`--travel-verification`）

> **先读这一句**：**本技能不做任何联网查询。** 核验数据**由你（或你的智能体）用你自己的方式取得后提供**。
> 技能只做一件确定、可复现的事：**把你的核验结果与报销单据逐字段比对**。

---

## 一、先把"能核验什么"分成三层（很重要）

| 层次 | 能不能核验 | 靠什么 |
|---|---|---|
| **① 票/行程单真伪** | ✅ **官方、免费** | 航信 / 民航局 / 航司官网「客票验真」（票号 + 姓名） |
| **② 航班是否存在 / 执飞 / 时刻 / 航段** | ✅ **准官方、便宜或免费** | 飞常准 / 飞猪开放平台 / 机场官网 / 民航局抵离港 |
| **③ 某人是否真的登机（乘客级 / PNR 级）** | ❌ **不公开** | 属**个人信息 + 航司商业数据**；无法独立公开核验 |

> **结论**：外部核验能给出"**票和航班对不上**"，**不能**直接得出"人没去"。
> 我们是**确定复核优先级**，不是下结论。

---

## 二、免费 / 公开渠道（已核实）

### A. 验"票是不是真的"（官方、免费）

| 渠道 | 地址 | 说明 |
|---|---|---|
| **中国航信 信天游** | `www.travelsky.com.cn` | 民航局**授权**的机票 / **行程单**验真 |
| **民航局官网 电子客票验真** | `www.caac.gov.cn` → 服务大厅 → 电子客票验真 | 官方；"航班信息由中国航信提供" |
| **各航司官网「客票验真」** | 国航 / 东航 / 南航 / 海航 等官网 | 输入**票号或行程单号 + 姓名**；各航司只验自家销售的票（如海航 880、南航 784 开头） |

> 这些是**"票真不真"的权威答案**：**票号在官方系统查不到 ⇒ 基本可判为假票**。
> ⚠️ 多为**网页 + 验证码**，自动化困难，通常需要**人工核对**（或由具备浏览能力的智能体辅助）。

### B. 验"航班是否存在 / 执飞"（准官方、便宜或免费）

| 渠道 | 费用 | 能力 / 备注 |
|---|---|---|
| **飞常准 MCP** `mcp.variflight.com` | **邮箱自助注册**、无需企业资质、有**试用额度**，超出按次 | ⭐ **为 AI Agent 设计（MCP）**，**官方支持 WorkBuddy / Claude / Cursor / Coze**；可按航班号 + 日期查**计划/预计/实际起降** |
| **飞猪开放平台** `alitrip.flight.dynamic.query` | 文档标注 **"免费 API、不需要授权"** | 按**航班号 + 日期**返回航段 / 状态 / 计划与实际起降；需注册开发者 |
| **机场官网 / 民航局「抵离港信息」** | **免费** | 首都（`bcia.com.cn`）、浦东、白云等机场航班实况；民航局官网列了各机场查询入口与电话 |

### C. 国际 / 历史 / 补充

| 渠道 | 费用 | 说明 |
|---|---|---|
| **OpenSky Network** | 科研/非商业**免费** | ADS-B **航迹历史**；**不含**航班时刻/延误；商业需授权 |
| FlightAware AeroAPI | 免费额度约 $5/月，含历史 | 覆盖好；超出付费 |
| Aviationstack / AeroDataBox / Aviation Edge | 免费额度小（100 次/月 · 600 单位/月 · $7 起） | **历史**通常属付费档 |
| OAG / Cirium | 企业级 | 时刻 / 动态 / 历史，不公开 |

> **成本真相**：贵的是**实时 + 高频轮询**；**报销是"事后、一票一查"，成本几乎为零**。
> 所以"历史数据查不到/要收费"这个担心，对**一次性核验**基本不成立。

## 三、输入格式

CSV / XLSX，**一行 = 一张报销单的核验结果**：

| 列 | 含义 |
|---|---|
| `expense_id` | **必填**：对应报销台账里的单据号 |
| `flight_no` / `travel_date` / `depart_city` / `arrive_city` / `passenger` | 外部**实际**查到的值；**查不到就留空** |
| `pnr` | 订座号（可选） |
| `source` | 来源（会写进 finding，供复核）；建议填 |
| `source_reliability` | 可选：`official` / `commercial` / `consumer` / `unknown` |

```csv
expense_id,flight_no,travel_date,depart_city,arrive_city,passenger,source,source_reliability
F1,CA1234,2026-10-09,北京,上海,EMP1,航司官网,official
F2,,,,,,航旅纵横,consumer
```

## 四、会产生什么

| 情况 | 结果 |
|---|---|
| 查到且一致 | **不产生** finding |
| 查到但不一致（航班号 / 日期 / 方向 / 乘机人） | `travel-verification-mismatch`（**强**） |
| **在给定来源中查不到**（外部字段全空） | `travel-verification-not-found`（**弱**） |
| 报销单没有对应核验行 | 不核验，只在 `data_quality.md` 里计数 |

---

## 五、红线：**「查不到」不等于「虚构」**

- 外部来源可能**覆盖不全、字段不全、查询范围有限**——"没匹配到"**只是弱信号**；
- 结论里会**明确写出**这一点；
- 与 `cn-entity-relation-check` 的「**没查到 ≠ 不关联**」是同一条原则。

## 六、比"联网核验"更划算的一块：**凭证内部一致性**（完全离线）

一张**凭空捏造**的机票/行程单，通常在**内部就自相矛盾**——这些**不用联网**就能查。
本技能提供可选规则 `voucher_consistency_check`（默认关闭）：

| 规则 | 检查 |
|---|---|
| `ticket-number-reused` | 同一**票号**在台账里重复出现（同票多报 / 多人共用一票） |
| `ticket-issue-after-flight` | **出票日期晚于**行程/费用日期（先飞后出票） |
| `itinerary-segment-conflict` | 同一**订座号**同一天出现**多个不同航段** |

> 再加上 `voucher_completeness_check`（缺发票号 / 发票日期）——**"没给任何凭证"本身就是信号**。

## 七、在图形界面（WorkBuddy / Claude Desktop / 豆包等）里怎么用 ⭐

**你不需要自己在命令行里敲参数。** 在图形界面里，**是智能体去运行脚本**——你要做的是**把核验结果交给它**：

- **方式 1（最常见）**：直接对智能体说
  > "这是我查到的航班核验结果：……（或：文件在 `D:\xxx\核验.csv`），请用它核验这批报销单。"

  智能体会把内容整理成上面格式的 CSV，再带 `--travel-verification` 运行技能。
- **方式 2（让智能体去查）**：对智能体说
  > "请帮我查这几张机票对应的实际航班，再核验报销单。"

  智能体有联网/搜索/MCP 能力（如飞常准），查完按格式落盘 → 再运行。

**只有当你自己在终端/命令行里跑脚本时**，才需要手敲：

```bash
python3 scripts/run_expense_audit.py --input 台账.csv --travel-verification 核验结果.csv --output out/
```

> 也就是说：`--travel-verification` 是**给智能体 / 命令行用的接口**，**不是要文员去记的命令**。
> `SKILL.md` 里已经把整套流程写清楚了，合格的智能体应当照做。
> ⚠️ 少数**只能聊天、不能执行代码**的宿主，无法真正跑脚本——那时只能由智能体自己做比对（会失去"确定性/可复现"）。

## 八、谁负责联网

**你（或你的智能体）。** 宿主智能体一般自带联网/搜索/MCP 能力——**由它在你的许可下取数，再喂给本技能**。
这样：**取数的责任和使用者的合规评估在你这边**，而**被审计的那个技能包始终是干净的**。

> ⚠️ **合规提醒**：请以各来源的**官方条款**为准。抓取"需授权 / 禁止自动化"的来源，**风险由使用方承担**——
> 这也正是我们**不把联网写进技能**的原因之一。
