# 数据源连接引导（provider-onboarding）

当本 skill 在运行时发现「没有可用的结构化企业数据源」时，必须把结论降级为「待核查」，并在 `warnings` 里附上下面这段引导，**而不是凭记忆或网页检索编造「关联/不关联」**。

引导的三个目标：

1. 一句话讲清「为什么现在只能待核查」。
2. 给出「下一步」，且反复强调**一次性**（降低审计师的心理负担）。
3. 永远留一个「先继续」的出口（Web 兜底），不阻断任务。

---

## 通用骨架

```
⚠ 本次只能先给你「待核查」，因为现在还没连上企业数据源。

判断「关联 / 不关联」要靠真实的工商数据（股东、法人、董监高、投资这些），
光靠网页检索只能证明「有关系」，没法可靠证明「没关系」。

下一步（任选一个，都是一次性的）：
  ① 连企查查（推荐，最省事）
  ② 用你自己的 API Key（懂一点技术再选这个）
  ③ 先用网页检索继续（结论会受限，多数是「待核查」）
```

## 平台变体（只替换「① 连企查查」那段）

### WorkBuddy（内置连接器）

```
① 连企查查（推荐，约 30 秒，一次性）：
   左侧【连接器】→ 找到【企查查】→ 点 + → 登录企查查账号 → 显示「授权成功」即可。
   没有企查查账号？用手机号或微信注册一个（注册完会自动记住，以后不用再登）。
   连好后回来重新问我一次，我马上重查。
```

### 阿里 QoderWork（内置连接器）

```
① 连企查查（推荐，1 步）：
   【连接器】里把【企查查 MCP】打开，登录企查查账号即可。
   连好后回来重新问我一次。
```

### 通用 MCP 客户端（Cursor / Claude Code / CherryStudio 等）

```
① 连企查查（推荐，约 3 分钟，一次性）：
   1. 打开 agent.qcc.com，注册/登录企查查账号，在个人中心复制你的 API Key；
   2. 把企查查给的 MCP 配置粘进你的 MCP 设置里，保存后重启软件；
   3. 回来重新问我一次即可。
```

### 兜底（识别不出平台时，直接问）

```
你现在连了哪个企业数据源？（企查查 / 天眼查 / 启信宝 / 都没连）
连了就告诉我一声，我马上重查；没连的话我可以一步步教你怎么连，
或者先用网页检索给你一个受限结论。
```

## 必须加的回退句（处理「其实已连接但我没探测到」）

```
如果你其实已经连过企查查、只是我没探测到，直接告诉我「连了企查查」，我重试一次。
```

> Agent 自省自己的连接器并不可靠，这句能兜住「误判成没连」的情况，避免用户白折腾。

---

## 设计原则（为什么这么写）

1. **先说「为什么只能待核查」**，不说「MCP」「Connector」这类术语。
2. **反复强调「一次性」**——审计师最大的心理障碍是「这玩意要一直折腾」。
3. **永远给「先继续」的出口**（Web 兜底），不阻断任务，只降级结论。
4. **守 BYOK 边界**：全程用「你自己的账号 / Key」，绝不暗示「作者已经开通了」。
5. **平台感知**：同一套骨架，只有「① 连企查查」那段随平台换，其余不变。

## 数据源选择备注

- 首选引导 **企查查**：它原生支持「强语义负向防御」（能区分「查完没有」与「调用失败」），是第一个能完整满足本 skill 三态协议（尤其「不关联」前提）的数据源。
- 企查查 MCP 是通用 MCP 协议，除 WorkBuddy / 阿里 QoderWork 的内置连接器外，任意 MCP 客户端都能通过 `agent.qcc.com` 的 API Key 接入（14+ 平台）。
- 「微信扫码 + 手机号」是企查查账号注册的**一次性**要求，属数据商合规底线，任何方案都无法绕开——引导里要把它说成「一次性、以后自动记住」来降低顾虑。
